# 第三阶段评测脚本说明

本文档说明第三阶段已落地的三个评测脚本模块：

- `build_retrieval_set`
- `retrieval`
- `generation`

脚本入口统一为 [scripts/evaluate.py](C:/Users/xieyuxiang/Documents/RAG_medical/scripts/evaluate.py)。

---

## 1. 使用前提

- 目标 `collection` 已经存在于 Milvus 中。
- 目标 `collection` 默认是测试专用 collection，不应混入 `train` 或 `valid` 内容。
- Milvus 记录里的 `source_path` 和 `source_line_no` 仍然可回源到原始 JSONL 文件。
- 需要从项目根目录执行命令。

推荐调用方式：

```powershell
uv run scripts\evaluate.py --help
```

不要直接执行：

```powershell
scripts\evaluate.py ...
```

---

## 2. 模块一：`build_retrieval_set`

### 2.1 作用

从指定 Milvus `collection` 中构造第三阶段检索评测集，并为后续生成评估保留完整 `reference_answer`。

### 2.2 命令

```powershell
uv run scripts\evaluate.py build_retrieval_set --collection rag_medical_documents_test
```

常用写法：

```powershell
uv run scripts\evaluate.py build_retrieval_set --collection rag_medical_documents_test --sample-size 50 --seed 20260608 --output eval/datasets/retrieval_eval.jsonl
```

### 2.3 参数

- `--collection`：必填，目标 Milvus collection。
- `--sample-size`：可选，默认 `300`。
- `--seed`：可选，默认 `20260608`。
- `--output`：可选，默认 `eval/datasets/retrieval_eval.jsonl`。

### 2.4 实际处理流程

当前实现不是“全量扫完再抽样”，而是流式抽取前n条数据：

1. 用 `MilvusStore.iter_export_rows()` 只读遍历目标 `collection`。
2. 以 `(source_path, source_line_no, question)` 识别唯一候选组。
3. 收集到足够多的候选组后提前停止扫描，当前阈值为 `max(sample_size * 3, sample_size)`。
4. 对每个候选组调用 `export_rows_for_group()`，补齐该组全部 chunk 对应的 `doc_id`。
5. 将同组 `doc_id` 聚合为 `gold_doc_ids`。
6. 用 `source_path + source_line_no + question` 回源原始 JSONL，并通过 `clean_records()` 恢复完整问答。
7. 仅当完整答案能覆盖当前组所有 chunk `answer` 文本时，才接受为 `reference_answer`。
8. 无法唯一恢复完整答案的样本会被丢弃，并写入丢弃文件。
9. 在可用样本上执行最终抽样并生成 `sample_id`。

### 2.5 当前优化点

为避免小样本评测集也跑得很慢，当前实现额外做了三点优化：

- Milvus 侧采用早停抽样，不再默认扫完整个 collection。
- `MilvusStore` 会缓存 collection 已加载状态，避免按组补查时重复 `describe_collection` 和 `load_collection`。
- `reference_answer` 回源恢复按 `source_path` 分组批量读取，同一个源文件只扫一遍，不再每条样本都从文件头重读。

### 2.6 输出文件

- `eval/datasets/retrieval_eval.jsonl`
- `eval/datasets/retrieval_eval.discarded.jsonl`

脚本标准输出会返回一段 JSON 摘要，例如：

```json
{
  "collection": "rag_medical_documents_test",
  "candidate_count": 120,
  "scanned_rows": 90,
  "candidate_group_count": 90,
  "sample_count": 50,
  "discarded_count": 3,
  "output_path": "eval\\datasets\\retrieval_eval.jsonl",
  "discarded_path": "eval\\datasets\\retrieval_eval.discarded.jsonl"
}
```

### 2.7 评测集结构

`retrieval_eval.jsonl` 中每条样本固定包含：

```json
{
  "sample_id": "eval_000001",
  "query": "口干怎么办？",
  "gold_doc_ids": ["doc_1", "doc_2"],
  "reference_answer": "完整参考答案",
  "source": "encyclopedia",
  "source_path": "C:/data/test.jsonl",
  "source_line_no": 123
}
```

说明：

- `gold_doc_ids` 是数组，不是单值，用来兼容同一长答案被切成多个 chunk 的场景。
- `reference_answer` 固定从源数据回源恢复，不直接使用 Milvus 中的 `answer` 字段。

## 3. 模块二：`retrieval`

### 3.1 作用

基于 `retrieval_eval.jsonl` 对当前检索链路做召回性能评估，并直接复用真实 `/query` 调用路径。

### 3.2 命令

```powershell
uv run scripts\evaluate.py retrieval --dataset eval/datasets/retrieval_eval.jsonl
```

常用写法：

```powershell
uv run scripts\evaluate.py retrieval --dataset eval/datasets/retrieval_eval.jsonl --search-method all --top-k 10 --fetch-k 10 --output-dir eval/reports
```

### 3.3 参数

- `--dataset`：可选，默认 `eval/datasets/retrieval_eval.jsonl`。
- `--search-method`：可选，`dense` / `sparse` / `hybrid` / `all`，默认 `all`。
- `--top-k`：可选，默认 `10`。
- `--fetch-k`：可选，默认 `max(10, settings.fetch_k)`。
- `--output-dir`：可选，默认 `eval/reports`。

### 3.4 实际评估逻辑

1. 读取 `retrieval_eval.jsonl`。
2. 对每条样本调用 [app/api/main.py](C:/Users/xieyuxiang/Documents/RAG_medical/app/api/main.py) 中的 `query_documents()`。
3. 按 `dense`、`sparse`、`hybrid` 或指定单模式运行。
4. 用返回结果前 5 条计算 `Recall@5`。
5. 用返回结果前 10 条计算 `Recall@10` 和 `MRR`。
6. 只要返回结果中任一 `doc_id` 落在 `gold_doc_ids` 内，即视为命中。
7. 同时记录每次查询耗时，并汇总延迟指标。

### 3.5 输出文件

- `eval/reports/retrieval_summary.json`
- `eval/reports/retrieval_failures.jsonl`

其中：

- `retrieval_summary.json` 保存每种 `search_method` 的总体指标。
- `retrieval_failures.jsonl` 保存未命中 `Recall@10` 的失败样本。

### 3.6 汇总指标

`retrieval_summary.json` 至少包含：

- `sample_count`
- `recall_at_5`
- `recall_at_10`
- `mrr`
- `latency_p50`
- `latency_p95`
- `meets_recall_at_10_target`

其中 `meets_recall_at_10_target` 对应阶段目标：

```text
Recall@10 >= 0.75
```

## 4. 推荐使用顺序

先生成评测集：

```powershell
uv run scripts\evaluate.py build_retrieval_set --collection rag_medical_documents_test --sample-size 50
```

再跑检索评估：

```powershell
uv run scripts\evaluate.py retrieval --dataset eval/datasets/retrieval_eval.jsonl --search-method all
```

最后跑生成评估：

```powershell
uv run scripts\evaluate.py generation --dataset eval/datasets/retrieval_eval.jsonl --output-dir eval/reports
```

## 5. 模块三：`generation`

### 5.1 作用

基于 `retrieval_eval.jsonl` 逐条调用真实 `/answer` 链路，并在离线评估产物中补充：

- 回答正文
- 正文真实引用 `citations`
- 检索候选 `retrieval_results`
- 程序化检查结果
- LLM Judge 结构化 `grade`

### 5.2 命令

```powershell
uv run scripts\evaluate.py generation --dataset eval/datasets/retrieval_eval.jsonl
```

常用写法：

```powershell
uv run scripts\evaluate.py generation --dataset eval/datasets/retrieval_eval.jsonl --output-dir eval/reports --top-k 5 --sample-limit 10
```

### 5.3 参数

- `--dataset`：可选，默认 `eval/datasets/retrieval_eval.jsonl`。
- `--output-dir`：可选，默认 `eval/reports`。
- `--top-k`：可选，默认环境变量 `settings.top_k`。
- `--sample-limit`：可选，默认不限制，用于小样本试跑。

### 5.4 实际评估逻辑

1. 读取 `retrieval_eval.jsonl`。
2. 对每条样本调用 [app/api/main.py](C:/Users/xieyuxiang/Documents/RAG_medical/app/api/main.py) 中的 `answer_query()`。
3. 记录回答正文、`fallback`、正文真实引用 `citations`、完整检索候选 `retrieval_results` 和回答耗时。
4. 先执行程序化检查，覆盖空回答、引用存在、`fallback` 记录、延迟阈值和高风险问题升级提示。
5. 再调用独立 Judge 模型，输出固定 `grade + reason` 结构打分。
6. 最后在汇总阶段做 `fail -> 0`、`warning -> 1`、`pass -> 2` 的统一映射，并生成 summary。

### 5.5 Judge 输入语义

- `context_relevance` 主要根据 `retrieval_results` 判断检索是否找对资料。
- `faithfulness` 主要根据 `citations` 判断回答是否被正文真实引用的依据支持。
- `reference_answer` 只作为弱参考，不作为逐字对齐金标。

### 5.6 输出文件

- `generation_results.jsonl` 保存逐样本完整结果。
- `generation_summary.json` 保存主评分、安全专项、分诊专项和延迟统计。
- `generation_failures.jsonl` 保存 `judge_error`、程序化检查失败、或任一维度 `warning/fail` 的样本。

### 5.7 单样本结果结构

`generation_results.jsonl` 中每条样本至少包含：

```json
{
  "sample_id": "eval_000001",
  "query": "口干怎么办？",
  "reference_answer": "完整参考答案",
  "answer": "生成回答",
  "fallback": false,
  "citations": [],
  "retrieval_results": [],
  "latency_ms": 1234.5,
  "program_checks": {},
  "llm_judge_result": {},
  "judge_error": false,
  "judge_error_reason": null
}
```

说明：

- 单样本阶段只存 `grade`，不存数值 `score`。
- `citations` 与 `retrieval_results` 语义不同，不能混用。
- `judge_error=true` 时样本仍保留，不会被静默丢弃。

### 5.8 汇总指标

对所有样本打分结果进行汇总统计，展示在`generation_summary.json` 中

字段包含：

- `sample_count`
- `scored_sample_count`
- `judge_error_count`
- `fallback_rate`
- `latency_p50`
- `latency_p95`
- `core_total_score`
- `core_average_score`
- `dimension_stats`
- `safety_fail_rate`
- `safety_warning_rate`
- `hard_risk_label_hit_rate`
- `safety_risk_label_distribution`
- `triage_fail_rate`
- `triage_warning_rate`

### 5.9 当前边界

- `build_retrieval_set` 当前是“快速早停抽样”，不是严格全量随机抽样。
- 评测集的金标来源于现有 Milvus 与源数据回源，不是人工标注。
- llm评估维度`medical_correctness` 由于缺少专家资料；没有相关金标；当前仍是低置信度辅助维度。
